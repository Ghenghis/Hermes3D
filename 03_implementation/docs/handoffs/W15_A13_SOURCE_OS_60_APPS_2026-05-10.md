## 2. Honest-readiness contract (no fake "Ready")

A card is marked **Ready** only when BOTH:

1. `proof_command` is present and non-empty in the `/api/apps` payload.
2. `last_proof_status ∈ {"passed", "pass"}`.

Anything else maps to:

| Condition | Label | Tone |
|---|---|---|
| `proof_command` missing | `—` (em-dash) | muted / amber dot |
| `proof_command` present + `last_proof_status="failed"|"fail"` | `Blocked` | rose |
| `proof_command` present + `last_proof_status="pending"|"running"` | `Proving` | cyan, animated |
| Else (e.g. `null`) | `Unknown` | amber |

Today's backend snapshot:

```
/api/apps count: 60
proof_command present: 19 / 60
last_proof_status: null × 60
```

→ matrix coverage score: **0%** (0 of 60 proof-passed). 41 cards → `—`. 19 cards → `Unknown`. **No card is ever shown as Ready under current backend state.** That is the honest read.

## 7. Two sources cited

1. **Official — React Grid Layout sizing primitives**
   <https://github.com/react-grid-layout/react-grid-layout> — used as the
   reference for responsive grid math. The matrix opts for native CSS Grid
   (`auto-fill, minmax(168px, 1fr)`) over the JS engine because the layout is
   static (no drag/resize) and the bundle weight saving (~25 kB gzipped) is
   meaningful given the existing 993 kB main chunk.

2. **Cross-project — VS Code Marketplace extensions browse pattern**
   <https://marketplace.visualstudio.com/vscode> — informed the `AppCard`
   composition (avatar + name + version chip + status dot + action button) and
   the 60+ tile responsive grid. The marketplace's pixel-level extension card
   is the closest public mirror of the "60 modular surfaces with proof-state
   indicators" idiom the user's reference collage uses.
