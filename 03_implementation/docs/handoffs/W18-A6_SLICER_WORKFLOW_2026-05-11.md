## 3. Why this is FAIL_NOT_WIRED (per brief's hard rules)

The brief says PASS_REAL requires:

1. **Playwright spec drives the GUI slicer** — impossible: there is no GUI element to drive. `Slicing.tsx` was deleted in W15 cleanup, `Design.tsx` and `Jobs.tsx` have no "Slice" affordance, and `App.tsx` registers no `slice`-bearing route.
2. **Backend invokes a real slicer** — partially: a real slicer is invoked, but only via `python -m hermes3d slice`, **not** via any HTTP endpoint the GUI could call.
3. **Real `.gcode` file produced** — yes, demonstrated above (109 KB, real PrusaSlicer headers).
4. **UI shows layer count, time, file path/size** — impossible: there is no UI.

Three of four PASS_REAL criteria fail at the GUI / HTTP boundary. Per the brief, **classify and report; do NOT fabricate** a Playwright spec against missing surfaces.

The brief also prohibits installing a new slicer in this lane (PrusaSlicer is already installed, so this rule is satisfied trivially).
