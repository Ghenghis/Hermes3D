The first agentic 3D printing emporium.

Hermes3D-OS is more than an operating system. It is a 60-app, dual-Hermes, GPU-backed ecosystem for printing, designing, generating, and self-coding. Drop in an image — Hermes builds the mesh on your RTX 3090 Ti, switches generation models on command, truth-gates the result, slices it, and starts the print only when the build plate is clear. Two Hermes Agent teams (MiniMax-M2.7 builders + DeepSeek-V4 reviewers) extend the system itself in a Docker net=none sandbox under MCP locks. Anonymous to use. Fully agentic. GPU-backed · RTX 3090 Ti

Drop an image. Get a printed part.

Hermes orchestrates the whole image-to-print chain on your local GPU. Switch generation models on command. Truth-gate every mesh. Slice. Dispatch — only when the build plate is clear.

Model router

Hermes routes intent to the right engine: TRELLIS.2 for high-quality text-to-3D, Hunyuan3D 2.1 for image-to-3D production, TripoSR for fast preview, ComfyUI for graph-based workflows, OpenSCAD/CadQuery for parametric design.

Switch on command

"Switch to TripoSR for the next preview." "Run TRELLIS.2 at high quality on this image." "Re-render with the OpenSCAD parametric template." Every switch lands a proof event so the run history shows which engine produced which mesh.

One GPU broker

RTX 3090 Ti is a first-class scheduling resource. The GPU broker prioritises one job at a time, queues the rest, and yields the card back to the OS when idle. ComfyUI · TRELLIS.2 · Hunyuan3D · TripoSR share the same broker.

Auto-repair

Raw mesh hits Manifold + meshlab to close holes, fix flipped normals, and resolve non-manifold edges before the truth gate ever sees it.

Truth-gate every mesh

Six concurrent printability checks (manifold · walls · overhang · bridges · supports · first-layer area). HMAC-signed verdict. Repair loop bounces back to GENERATE up to N times if the gate fails.

STL · 3MF · gcode

Output formats follow the slicer of choice. Hermes preserves the proof envelope across format conversion so the artifact you print is the artifact you signed.

Autonomous, but only when safe

STOP before heat. Every time.

Hermes will start a print on its own — only when the build plate is empty, the last print has been removed, the camera observer reports no obstruction, and policy approval is in place. Any single failure halts the entire chain and alerts the user. No override without explicit user action.

Build-plate clear

Camera observer probes the live frame before any heater turns on. Previous part, brim, debris — anything triggers a HARD STOP. Heaters stay off. User alert until cleared.

Last-print removed

Job history requires bed_cleared=true ack between prints. Hermes refuses to start until the user clicks Bed Cleared or the camera confirms a clean surface.

No active alert

Filament-out, thermal runaway, layer shift — any open incident from the detector blocks the chain. Acknowledge and resolve first.

S1 read-only

The user's FLSUN S1 is locked by user policy. No autonomous action of any kind. T1#1 / T1#2 / V400 follow the cleared-plate gate.

Truth-gate pass

Mesh failed any of the six printability checks? HARD STOP. The repair loop must succeed before the slicer is invoked.

Approval policy

T1 / V400 may require explicit Print Approved per job (configurable). Hermes posts the approval to the Approvals tab and waits.

When the gate fires

STOP — Build plate not cleared. Remove the previous print and any tools, brims, or debris from the build surface, then click "Bed Cleared" to continue. Heaters will not turn on while this alert is active.

STOP — Cannot heat: cleared-plate proof missing. Hermes never heats the bed or hotend without a fresh cleared-plate confirmation. Resolve the open camera alert first.

STOP — Open incident on Printer T1#1. Filament-runout alert (ev_…) is unresolved. Acknowledge and resolve before queuing a new print.

The OS extends itself

Two Hermes teams. One coding loop.

Hermes3D-OS extends itself. Two distinct Hermes Agent teams, two distinct API keys, one bounded coding loop with MCP locks, snapshots, gates, and signed PRs.

Team A · MiniMax-M2.7 · Builders

High-speed builder team. Reads folder index, drafts patch proposals, runs scaffolding, suggests refactors. Folder-index-bounded. Lock-required. Never mutates source until Team B reviews.

Team B · DeepSeek-V4 · Reviewers

Reviewer team. Reads patch proposals, validates safety + security risks, checks proof IDs and gate results. Read-only on source. Approves or rejects. Reject sends back a repair plan.

OpenHands CLI 1.16.0

Sandboxed coding agent. Terminal · file · browser tools. Inside Docker, never on the host directly.

OpenCode 1.4.3-hermes3d

Bounded code runner. Detected from private env. Write-capable runs require lock + snapshot + gates + review.

Hermes3D-OS is not a chatbot you open and close. It is an always-running OS layer. When there is no active user job, the two Hermes Agent teams use idle time to improve the system — and every change they ship is proved before you ever see it.

Pipeline

Nine stages, one source of truth.

Every print walks the same orchestrator state machine — from intent to delivery — and emits structured evidence at every transition.

Deterministic dry-run

Walk the entire pipeline without an LLM, network, or printer. The state machine is the same. Use it for tests, for CI, for ground-truth comparison against the autonomous mode.

LangGraph + checkpoints

Switch the same orchestrator to LangGraph runtime and you get conditional edges, checkpointing, retry-with-context, and observable agent traces — without rewriting a single stage.

Repair loop

Stage 04 is allowed to bounce back to GENERATE up to N times when the truth gate fails. The repair iteration count is part of the evidence — silent regressions cannot hide.

Truth Gate

Six independent verifications. One signed verdict.

Drop an STL into the launcher and Hermes3D runs six concurrent printability checks, then HMAC-signs the verdict so it can be verified later — even by parties who don't trust the printer that ran the job.

Manifold closure

Watertight surface required. No floating triangles, no flipped normals, no holes the slicer would silently fill.

Wall thickness

Minimum wall thickness vs. configured nozzle diameter. Caught before the first layer is committed to gcode.

Overhang & bridges

Slope above 45° and unsupported spans > 25 mm flagged. Surfaceable by the auto-orient agent into a printable orientation.

Support estimate

Predicted cm³ of support material, factored into cost estimate and feasibility.

First-layer area

Bed adhesion is one of the top failure modes. Hermes computes it and gates on it.

HMAC envelope

Verdict + check matrix + source mesh hash + run timestamp, signed with a per-instance key. Tampering invalidates the seal.

MCP coordination · 44 tools · 220 routes

Six AI clients. Forty-four tools. One governed surface.

Hermes3D ships an MCP server with 44 tools that any compliant client can call — locks, tasks, A2A, handoffs, evidence, gates, doctor, anonymous claims, agent health, queue. The FastAPI runtime exposes 220 HTTP routes including the 10 required Agent Workbench routes for the dual-Hermes coding loop. HermesProof's governance layer makes sure concurrent agents don't step on each other.

Per-file locks

Every concurrent agent must claim a lock on the files it intends to edit. The lock is atomic (mkdir EEXIST), TTL-expiring, and ownership-checked server-side. No two agents stomp.

Hash-chained evidence

Every tool call appends to an evidence ledger where each entry binds to the previous via prev_hash + entry_hash. Mid-chain tamper detected on the next verify.

Atomic handoffs

Need to hand a task from Codex to Claude for review? Single tool call, evidence-emitting, ownership-tracked, blocked-handoff fallback for safe failure.
